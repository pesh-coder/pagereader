# F1–F10 check against the spike package set

Checked 2026-10-15. These are source/API checks, **not** observations of BSV Desktop or BSV Browser. Their actual app versions remain unrecorded. A wallet may use a different permissions-manager implementation or package version; E1/E2/E3/E6/E4 remain necessary.

Exact runtime packages: `@bsv/sdk@2.8.11`, `@bsv/auth-express-middleware@2.2.9`, `@bsv/payment-express-middleware@2.1.9`, `@bsv/wallet-toolbox-client@2.14.9`, `express@5.1.0`. These are installed locally under `spike/node_modules/`; lockfile integrity pins the downloaded artifacts. TypeScript 5.8.3, tsx 4.20.6 and esbuild 0.28.2 are pinned build tools.

| Fact | Check | Evidence in exact installed packages / qualification |
|---|---|---|
| F1 Monthly per-app allowance and grants | Source-confirmed reference behavior; actual wallets UNRESOLVED | Toolbox client `out/index.client.mjs`: `ensureSpendingAuthorization`, token grant/renewal paths, `getCurrentMonthYearUTC`, `querySpentSince`. Reference accounting uses a UTC calendar month and originator labels. Ephemeral/denied/granted behavior exists; actual options/wording require diary. |
| F2 Fees count against allowance | Source-confirmed reference accounting; actual fees UNRESOLVED | Same file: `querySpentSince` totals negative net action satoshis via `listActions` with originator/month labels. Actual action fees and wallet UI reconciliation have not been measured. |
| F3 Manifest grouped prompt | Candidate schema/API confirmed; one-prompt UX UNRESOLVED | Toolbox declarations `out/index.client.d.mts`: `GroupedPermissions`, `spendingAuthorization.amount`, `protocolPermissions`. Runtime `fetchManifestGroupPermissions`, `isRequestIncludedInGroupPermissions`, grouped permission flow and `seekGroupedPermission` flag. Fallback and peer trust may produce more prompts. Candidate manifest covers SDK `auth message signature`, self `server hmac`, and BRC-29 derivation against server identity. |
| F4 BRC-105 differs from BRC-121 | Confirmed selected package contract | Payment package README and `dist/src/index.mjs` use auth identity, version 1.0, `x-bsv-payment`, prefix/suffix/AtomicBEEF, output 0. SDK `AuthFetch.js` uses the same contract. BRC-121 is not installed or used. Its separate headers are a specification distinction, not a run of that package. |
| F5 Stack's 402 guide is a different protocol | Documentation context only; not a runtime dependency | Original guide and BRC-121 links in plan remain research references. Implementation is verified against the pinned BRC-105 SDK/middleware source instead. No code from the BRC-121 guide was used. |
| F6 Replay/underpayment and claim ordering | Source-confirmed; live negative checks deferred to tier 2 | Payment `dist/src/index.mjs`: output-0 underfunding yields 400 `ERR_INVALID_PAYMENT`; wallet verdict is validated before `replayStore.claim`; duplicate/merge or existing claim yields 409; store failure after wallet acceptance yields 503. Memory default is process-local. Probe injects SQLite `INSERT OR IGNORE`. This does not make wallet+database atomic. |
| F7 Auth identity, 401, sessions | Source/API and unpaid local HTTP integration confirmed | Auth package `dist/src/index.mjs` / declarations document `req.auth.identityKey`, default unauthenticated rejection, `SessionManager` / `AsyncSessionManager`. Local SDK-signed `me` and bookmark test passes without payments. Probe is one process, not replicated hosting. |
| F8 Payment retry can resend a paid tx | Source-confirmed; lost-response test deferred | SDK `dist/esm/src/auth/clients/AuthFetch.js`, `handlePaymentAndRetry`, `paymentContext`, `getMaxPaymentAttempts`: default max 3, context reused for the same challenge; changed challenge can create another transaction. Probe uses `paymentRetryAttempts: 1`, separates read-only status/owned routes, and does not reissue uncertain intents. |
| F9 Payment can leave before server page response | Defaults source-confirmed; wallet broadcast behavior UNRESOLVED | SDK `dist/esm/src/wallet/validationHelpers.js` defaults `signAndProcess` and `acceptDelayedBroadcast` true; AuthFetch calls createAction before paid HTTP submission. A returned wallet action is not proof of mining or network acceptance. Probe observes its txid and marks pending immediately; fee and interruption behavior remain tier-2/3 checks. |
| F10 BRC-29 derivation | Source-confirmed client and server contract | SDK AuthFetch uses `[2,'3241645161d8']`, prefix + space + suffix, server identity as counterparty, output 0 with randomization off. Middleware supplies prefix/suffix and authenticated sender identity to `internalizeAction`. No custom derivation/signature code is used. |

No reader seed or key was accessed.
